\subsubsection{Network simulation platform}
\label{sec:trial_grids}

The FLISR Edge simulation platform enables the simulation of fault events which will serve
to both test and evaluate the FLISR algorithms in lieu of actual hardware, these simulation are based on the distribution grid topologies obtained from the Synergy GIS output
described previously. The simulation platform leverages a micro service-like architecture, whereby services are loosely coupled, in addition these services are hosted within a
containerised environment via ``Docker'', and utilise ``docker-compose'' to enable simple deployment on either local systems or to a remote host \cite{7436659}. \hyperref[fig:sim_arch]{Figure \ref{fig:sim_arch}}
describes the architecture implemented for the simulation platform with a description of each service following.

\begin{figure}[h]
  \centering
  \includegraphics[width=0.5\textwidth]{fig_sim_arch}
  \caption{\label{fig:sim_arch}FLISR simulation platform architecture}
\end{figure}

\begin{itemize}
  \item \textbf{Databases}
\end{itemize}

\noindent
Two database services are in place which serve varying needs of the simulation platform, the first hosts the grid topologies with a ``Neo4j'' instance for both visualisation and simulation
purposes. The second database is intended to host the simulation results in a relational SQL format, which can then be served to the user via browser or exported to CSV for analysis.

\begin{itemize}
  \item \textbf{Grid topology service}
\end{itemize}

\noindent
The grid topology service consists of a Python Flask server which provides an interface to request information relating to the grid topology, such as specific assets, asset data etc.,
In addition, this service generates ``GeoJSON'' from the grid topology data which is used to visualise the trial site distribution grids.

\begin{itemize}
  \item \textbf{Simulation service}
\end{itemize}

\noindent
The simulation service serves as the largest and most complex, which also consists of a Python Flask server. Unlike the grid topology service, the simulation service queries for specific
data and contains functionality in order to run fault simulations and provide and outward interface to pass data to visualise these simulations. This service also interacts directly with the
FLISR Edge algorithms and simulates control on the edge devices. On completion of a simulation, the results are stored in the relational database.

\begin{itemize}
  \item \textbf{Reporting service}
\end{itemize}

\noindent
The reporting service again consists of a Python Flask server and REST interface. The key purpose of this service is to query, parse and process simulation result data stored in the Postgres database,
for visualisation to the user and for analysis purposes by exporting to CSV format.

\begin{itemize}
  \item \textbf{Visualisation service}
\end{itemize}

\noindent
Finally, the visualisation service consists of a React front-end which serves a graphical user interface to the user where the distribution grids and simulations are visualised. The UI contains
controls to set up and run simulations, view the simulation process, simulation results and the option to export these results for analysis. ``GeoJSON'' and ``LeaftletJS'' are leveraged to parse geolcation data,
via ``OpenStreetMap''.
